# flowork 引擎 v1 · 需求规格（收敛版）

> 取代 `agent-gateway-v1/02-需求规格.md`。[00-收敛版产品定义 §3](00-收敛版产品定义.md) 是 FR 摘要，**本文是详细规格（口径以本文为准）**。全部 FR 溯源到 [03-用户故事](03-用户故事.md) 的 US 编号；语义细节引用 [01 身份与组织模型](01-身份与组织模型.md)、[02 权限模型](02-权限模型.md)。优先级：P0=发布门槛；P1=发布目标；P2=已排期下版本。

## 1. 范围

**In scope（v1.0）**：目录（部门树/用户/范围化角色/Agent 一等身份/CSV）、权限（三类凭证/scope/RBAC/资源可见性/on_behalf_of）、定义与设计器（既有能力挂权限+变量 schema）、运行时开放面（REST 实例/任务 + MCP 8 工具 + webhook）、极简任务页、docker 自托管。

**Out of scope（防蔓延，去向见 00 §2 处置表）**：风险策略/信任档/上岗证/自动通过（v2 授权层）、IM 卡片（v1.1）、控制台四视图（v1.x 起）、钉钉/飞书/LDAP 同步（v1.1）、多租户（v2）、SoD 角色互斥（v2）、表单设计器、CS108 报告模板。

## 3. 非功能需求（NFR）

| ID | 维度 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 自动路由节点推进 P95 < 100ms；任务列表（万级）< 500ms；目录解析命中缓存（变更失效） |
| NFR-02 | 一致性 | 发起幂等（键唯一约束）；所有写走引擎乐观锁命令管线；凭证吊销读路径强一致（≤1s） |
| NFR-03 | 安全 | 凭证哈希存储；全部写操作带 actor 归因（凭证→principal 是 acted_by 来源）；结构化日志含 request_id 贯穿 REST/MCP/引擎 |
| NFR-04 | 审计完整性 | 历史/审计只追加，无 UPDATE/DELETE 路径；定义/目录变更均留痕 |
| NFR-05 | 兼容纪律 | 引擎核心零侵入（新能力只经 SPI/新模块/web 路由组，AGENTS.md 硬约束 2/3）；单文件 ≤300 行；MCP 工具面冻结 8 个 |
| NFR-06 | 可移植 | SQLite/Postgres 双栈；时间戳 naive UTC（flowork.clock）；无外部强依赖（webhook/IM 为可选外呼） |
| NFR-07 | 开发者体验 | REST OpenAPI 自描述；MCP 工具描述含幂等/超时语义；10 分钟 quickstart 文档（三方各一：Agent/第三方应用/运维） |

## 4. 发布验收门槛（DoD）

1. 全部 P0 FR 逐条按对应 US 的 Given/When/Then 核验通过。
2. **三线端到端演示各 < 5 分钟**：①Agent 线——MCP 客户端发现报销流程→fw_start_flow→老周任务页批准→wait 返回终态；②第三方线——api_key 替小陈发起（on_behalf_of）→webhook 收终态；③治理线——CSV 导目录→建角色授权→restricted_start 生效→审计 API 拉证据链。
3. 权限回归：同一用例集在 REST 与 MCP 双通道结果一致；越权全 404。
4. 工程四道门全绿：pytest（新模块覆盖 ≥90%）+ ruff + mypy strict；引擎既有 236+ 测试零回归。
5. 自托管冒烟：docker compose up → 跑通三线演示；upgrade 演练（v1.0 数据升 v1.1 占位用例）。
6. 文档齐备：三份 quickstart + API 参考 + 目录/权限管理员指南。

## 6. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 目录范围解析语义写错（主管/角色范围） | 全部审批路由错人 | 测试先行：01 §2 语义表逐条转用例，含"华东/华南/全局"三段用例 |
