# flowork 引擎 v1 · 用户故事（收敛版）

> 取代 `agent-gateway-v1/01-用户故事.md`（旧故事按 [00-收敛版产品定义 §2 处置表](00-收敛版产品定义.md) 分流，§5 有新旧对照）。范围权威 = 00 文档；身份/权限语义详见 [01](01-身份与组织模型.md)/[02](02-权限模型.md)。验收标准用 Given/When/Then，P0 故事必写。

## 1. 产品一句话与三类调用方

**可独立部署的流程引擎：内置组织身份与权限，REST + MCP 双开放。**

| 调用方 | 进来的路 | 干什么 |
|---|---|---|
| AI Agent | MCP（8 工具薄面）或 REST | 发现流程、发起实例、等待结果；也可作为审批人办任务 |
| 第三方应用 | REST（api_key） | 在引擎上构建自己的审批功能（报销/ERP/低代码），代人发起 |
| 组织里的人 | 任务页 / 设计器 / 管理 API | 设计审批流、办理任务、管理目录与凭证 |

## 2. 角色（Personas）

| ID | 角色 | 画像 | 核心诉求 |
|---|---|---|---|
| P1 | **阿凯 · Agent 应用开发者** | 给 Claude/自研 agent 接审批链的工程师 | 10 分钟 MCP 接入；等待-恢复别把 agent 搞崩 |
| P2 | **秦朗 · 第三方应用开发者**（新增，API 开放的首要受众） | 在引擎上做报销应用/对接 ERP 的后端 | REST 完整自洽、幂等、webhook；不用懂 BPM 内部概念 |
| P3 | **老周 · 审批人** | 财务/主管/值班工程师 | 任务页 30 秒看懂并办完；驳回要有意见 |
| P4 | **林姐 · 组织管理员** | 管"谁是谁、谁能干什么" | 10 分钟搭出目录；凭证安全可控 |
| P5 | **苏芮 · 流程设计者**（新增，传统审批流构建者） | 业务分析师/IT，维护审批制度 | 可视化构建传统审批流；发布前能试演 |
| P6 | **何敏 · 审计/合规** | 应对内审外查 | API 拉全量证据链，"谁提的谁批的"一问即答 |
| P7 | **大刘 · 自托管运维** | 私有云/机房 | docker 一条命令；升级不丢数据 |

（员工"小陈"不再是独立角色：他提交报销的入口由 P2 的第三方应用或任务页承载，其诉求并入 P2/P3 的故事。）

## 3. 史诗与故事

### E1 目录与身份（主角：林姐）

**US-101（P0）搭建部门树**
作为林姐，我希望建带层级的部门并给每个部门指定主管，以便"直接主管审批"开箱即用。
- Given 部门树上"市场部"的 manager=周主管，When 流程节点参与者为 `manager`，Then 实例推进时任务落到周主管（接通既有参与者函数）。
- Given 删除有子部门/在职人员的部门，When 调 DELETE，Then 被拒并提示先迁移。

**US-102（P0）维护用户**
作为林姐，我希望增删改查用户并指定主属部门，以便目录覆盖全体参与者。
- Given 用户小陈主属"市场部"，When 解析 `manager_of(小陈)`，Then 返回市场部 manager。
- Given 用户停用，When 其仍有待办，Then 待办按既有"无参与者兜底"策略处理，不悬死。

**US-103（P0）定义范围化角色**
作为林姐，我希望建角色并授权给（某部门范围内的）人，以便"找财务"能解析到正确的人。
- Given 角色"财务"授权给了华东子树的张三、全局的李四，When 发起人属华东某部门时解析 `users_with_role("finance")`，Then 返回张三（不含李四）；When 发起人属华南，Then 沿树向上未命中后返回李四。
- Given 同一范围命中多人，Then 全部返回，会签与否由流程定义决定（目录只给人）。

**US-104（P0）注册 Agent**
作为林姐，我希望为每个 AI 身份建档：负责人、所属部门、可选"代表某人"，并发放一次性凭证，以便 AI 有名有姓有问责。
- Given 创建成功，Then 凭证仅展示一次，哈希落库；列表可见 owner/部门/状态。
- Given Agent 停用，Then 其凭证的新调用立即 401，在途实例按兜底策略处理。
- Given 配置了 on_behalf_of=小陈，Then 该 Agent 发起的实例 started_by 归因小陈、acted_as_agent 附注该 Agent。

**US-105（P1）CSV 批量导入**
作为林姐，我希望用三张 CSV 模板（部门/用户/角色授权）一次导入存量组织，以便不逐条录入。
- Given 导入文件含冲突行，Then 逐行报告成功/失败，事务不整体回滚（幂等可重跑）。

**US-106（P1）目录变更留痕**
作为林姐，我希望目录的每次增删改都有操作人与时间记录，以便组织调整可追溯。

### E2 权限与凭证（主角：林姐；涉及阿凯/秦朗）

**US-201（P0）签发三类凭证**
作为林姐，我希望给用户发 token、给 Agent 发凭证、给第三方应用发 api_key，各自带作用域，以便一套体系管住所有调用方。
- Given 签发 api_key 时选择角色模板 member 并增删 scope，Then 凭证实际权限与勾选一致（中间件按 scope 判定）。
- Given 凭证过期时间已过，Then 调用立即失效。

**US-202（P0）平台角色与授权**
作为林姐，我希望把 admin/designer/operator/auditor/member 绑给用户，以便控制台与 API 操作各归其位。
- Given 老周只有 member，When 他调 definitions:write 类接口，Then 被拒；办自己的任务正常。

**US-203（P0）吊销即时生效**
作为林姐，我希望吊销凭证立刻生效，以便泄漏时一键止血。
- Given 凭证被吊销后 1 秒内的调用，Then 401，且吊销动作本身进审计。

**US-204（P0）第三方代人发起（on_behalf_of）**
作为秦朗，我希望报销应用替小陈发起实例时带 `on_behalf_of=小陈`，以便审计归因到人、留痕到应用。
- Given api_key 发起未带 on_behalf_of，Then 默认被拒（除非应用开启"无人格模式"）。
- Given 带 on_behalf_of，Then 实例 started_by=小陈，via_application=报销应用，两者在历史中均可见。

**US-205（P0）定义发起白名单**
作为林姐，我希望给个别定义配"允许发起"名单（如财务专用流程只许财务角色/指定应用），以便敏感流程不被乱启动。
- Given 定义 restricted_start=[role:finance]，When member 用户直接发起，Then 被拒并提示；财务角色放行。

**US-206（P1）最小权限模板**
作为林姐，我希望按用途一键套用 scope 模板（只读审计/仅发起/全管理），以便不逐项勾选也不超发。

### E3 构建传统审批流（主角：苏芮；能力已建，故事从角色视角固化）

**US-301（P0）可视化设计审批流**
作为苏芮，我希望在设计器里拖出"主管→财务会签→驳回回主管"的报销流程，以便制度可视化落地。
- Given 用矩形分支节点配条件（金额>1000 走财务）与 advance_policy，When 保存草稿，Then 校验通过且可继续编辑（复用现有 designer 全部能力）。

**US-302（P0）发布前试演**
作为苏芮，我希望发布前用变量样例做路由预演，以便不拿生产实例试错。
- Given dry-run 输入金额 1200，When 执行，Then 返回完整路径预览（走财务分支）且不产生实例。

**US-303（P0）发布与版本 diff**
作为苏芮，我希望发布新版流程并先看与线上版的 diff，以便在途实例按旧版完成、新实例走新版（定义快照隔离，引擎既有语义）。

**US-304（P1）发起变量 schema**
作为苏芮，我希望给流程声明发起变量（名称/类型/必填），以便第三方与 Agent 发起时被自动校验。
- Given 定义声明 amount 必填，When 发起缺 amount，Then 422 结构化错误。

**US-305（P1）超时与升级配置**
作为苏芮，我希望给审批节点配 SLA 与"超时升级到上级"，以便流程不堵死（复用 Jobs 超时与参与者升级）。
- Given 节点 SLA 120min，When 超时，Then 任务升级至该审批人的直接主管，历史留痕。

### E4 运行时开放面（主角：阿凯/秦朗）

**US-401（P0）MCP 十分钟接入**
作为阿凯，我希望在 MCP 客户端配 endpoint+agent 凭证后直接用 8 个工具，以便不给 agent 框架做改造。
- Given 未注册凭证，When 调用任一工具，Then 返回 401 与注册指引。
- Given 已注册，Then `fw_list_flows` 返回可发起流程与变量 schema 摘要。

**US-402（P0）发起实例（幂等）**
作为秦朗，我希望 `POST /instances`（或 `fw_start_flow`）带幂等键，以便重试不产生重复审批。
- Given 相同 idempotency_key 重放，Then 返回原 instance_id。
- Given 定义号不存在，Then 404（而非 500）。

**US-403（P0）查询与等待**
作为阿凯，我希望 `get_instance` 查状态、`wait_instance` 长轮询挂起等待（终态或下一人工步骤变化），以便适配长任务 agent。
- Given 实例已终态，When wait，Then 立即返回。
- Given timeout 到达仍未变化，Then 返回当前状态而非异常。

**US-404（P0）办理任务**
作为老周，我希望 `complete/reject/delegate` 三个动作明确语义，以便跨界面（任务页/MCP/第三方）办理一致。
- Given reject 不带 comment，Then 被拒（意见必填）。
- Given 办理他人任务，Then 404。
- Given 会签节点一人批准，Then 状态与剩余等待人正确更新。

**US-405（P0）我的待办**
作为老周，我希望拉到"我的待办"（含 AI 代我提交相关的），以便集中办理。
- Given 我是某任务的 assignee、另一任务的 candidate，When 拉取我的待办，Then 两者均返回并标注来源节点与已等待时长。
- Given 某实例由 Agent 以 on_behalf_of=我 发起，When 该实例任务到达我，Then 出现在我的待办，明细可见"AI 代提交"附注。

**US-406（P0）流程发现**
作为阿凯，我希望 agent 能自主发现可发起的流程及其参数要求，以便 zero-shot 接入新流程。
- Given `fw_get_flow(code)`，Then 返回变量 schema 与路由预览说明（复用 dry-run）。

**US-407（P1）Webhook 终态通知**
作为秦朗，我希望注册回调 URL 在实例终态/任务到达时被通知（HMAC 签名、失败退避重试），以便事件驱动而非轮询。

**US-408（P1）清晰错误语义**
作为阿凯，我希望所有错误结构化（错误码/人话/修复指引），404 优先于 403，以便 agent 能自纠。

### E5 极简办理界面（主角：老周）

**US-501（P1）任务页**
作为老周，我希望浏览器登录后看到待办列表（谁提的/什么事/多久了），点开即办，以便没有第三方界面也能用引擎。
**US-502（P1）驳回回路**：意见必填，发起方（应用/Agent）能拿到结构化驳回原因并整改重提。
**US-503（P1）转办/委托**：转给同事留痕 acted_by。
**US-504（P2）任务页多语言**：中英资源化。

### E6 审计（主角：何敏）

**US-601（P0）审计只读 API**
作为何敏，我希望按实例/时间/参与者拉全量历史（只追加、含双归因：谁发起（人/Agent/代人应用）与谁办理），以便回答"谁批的"。
- Given 任一实例，Then 历史含每个动作的 actor（human/agent）、时间、意见、定义版本。

**US-602（P1）多维检索**：按定义/发起人/状态/时间窗过滤。
**US-603（P2）导出**：CSV。

### E7 部署运维（主角：大刘）

**US-701（P0）一条命令自托管**
作为大刘，我希望 `docker compose up` 后引擎+API+任务页+worker 全部可用（默认 SQLite，可切 Postgres），以便私有环境 10 分钟上手。
- Given 首次启动，Then 自动建库并带一个示例流程，健康检查通过。

**US-702（P1）健康与指标**：/health；实例量/任务量/等待时延指标（Prometheus 文本）。
**US-703（P1）多副本**：web×n+worker×m 共库部署文档（Job CAS 恰一次已保证）。
**US-704（P2）备份恢复**：数据目录说明与恢复演练文档。
