# flowork 引擎 v1 · 可视化配置设计（Console）

> 要求①的落点："系统独立部署并通过 API 开放，但关键功能仍需可视化配置"。原则来自 [05 §1 三面同构](05-架构总体设计.md)：**Console 只是 REST 的视图**，本文定义它长什么样、先做哪些。

## 1. 什么算"关键功能"（可视化覆盖清单）

按"没有可视化就没人敢用/用不动"排序：

| 功能块 | 可视化必要性 | v1 | 备注 |
|---|---|---|---|
| 流程定义（设计/校验/dry-run/diff/发布） | 高——苏芮的日常 | ✅ P0 | **designer 既有能力直接并入**（本仓库已建：矩形分支/变量体系/路由预演/发布 diff） |
| 目录（部门树/用户/角色授权/Agent） | 高——林姐的日常，树形操作 CLI 不友好 | ✅ P0 | 新建 |
| 凭证与权限（签发/吊销/scope/平台角色） | 高——安全操作必须人审界面 | ✅ P0 | 新建；一次性明文弹窗 |
| 任务中心（待办/办理/驳回） | 高——老周的入口 | ✅ P1 | 简版（对应 UIA-01） |
| 审计检索与回放 | 中高——何敏按需 | ✅ P1 | 检索+时间轴+导出按钮 |
| 实例查询（运行中/历史/变量/历史轨迹） | 中——排障用 | ✅ P1 | 复用 dry-run 的路径可视化组件 |
| webhook/通知渠道配置 | 中 | P1 | 表单级 |
| 指标看板（Prometheus 直链/嵌入式） | 低 | P2 | 不自研图表 |

## 2. 信息架构（IA）

Console = designer 前端工程的新路由区块（`/console/*`），共享登录态（user_token）与请求层：

```
┌ 侧导航（按 scope 驱动显隐）────────────────┐
│ 流程                                        │
│  流程定义列表 → 编辑器（=既有 designer）       │
│  发布管理（版本/diff/回滚到旧版新建）           │
│ 组织                                        │
│  部门与主管（树形编辑器）                      │
│  用户（列表/CSV 导入向导）                    │
│  角色与授权（范围化，子树选择器）               │
│  Agent 名册（owner/凭证/on_behalf_of/停用）    │
│ 访问                                        │
│  凭证管理（三类/一次性明文/吊销）               │
│  平台角色分配 · scope 模板                    │
│  发起白名单（restricted_start 全局视图）        │
│ 运行                                        │
│  任务中心（我的待办/办件）                     │
│  实例查询（状态/变量/轨迹）                   │
│ 审计                                        │
│  审计检索 → 证据链回放 → 导出                 │
│ 系统                                        │
│  Webhook · 设置（保留策略等）                 │
└────────────────────────────────────────────┘
```

IA 决策：①"组织/访问"分列而非合并——林姐的心智里"谁是谁"与"谁能干什么"是两件事；②Agent 放在"组织"下（它是目录一等身份，01 文档），不放"访问"——凭证才在"访问"；③发布管理独立成页——版本是不可变资产，配 diff 视图。

## 3. 关键界面规格（P0 三块）

### 3.1 部门与主管（树形编辑器）

- 左树右表：选中部门显示名称/主管（用户选择器）/路径；拖拽移动子树（后端做环检测，422 带原因）。
- 删除保护可视反馈：有子部门/在职用户时删除按钮置灰并 tooltip 说明（DIR-01）。
- 主管变更即影响后续审批路由——保存时若该部门存在**进行中且含 manager 参与者节点**的实例，弹提示"仅影响新产生任务"（在途任务按创建时解析人，快照语义）。

### 3.2 角色与授权（范围化）

- 角色列表 + 每角色授权表（用户×范围）；范围选择器 = 部门子树（复用 3.1 组件）。
- **解析预演框**：选一个"模拟发起人"，实时显示 `users_with_role` 解析结果与路径（部门子树命中→向上→全局），把 01 §2 的范围解析规则变成看得见的东西——这是防错配的核心交互，也直接服务 H3 类假设验证。

### 3.3 凭证管理

- 三类凭证 tab；签发向导：选主体（用户/Agent/应用）→ 套 scope 模板 → 增删细项 → 有效期 → 签发。
- **一次性明文弹窗**（复制后不可再看的视觉强调）+ 建议录入调用方密管。
- 吊销需二次确认，展示"该凭证近 7 天调用数"辅助决策；吊销后列表即时置灰（≤1s 生效，PERM-01）。

## 4. 权限驱动 UI

- 导航与按钮按 scope 显隐/置禁用（member 只见"运行"组）；越权接口仍以后端 404 为准，前端隐藏只是体验不是安全边界（02 §4）。
- 操作留痕提示：目录/凭证/发布等敏感写操作，成功 toast 统一带"已留痕"字样，强化审计心智。

## 5. 与既有资产的关系

- designer 现有功能（分组面板/字段校验/变量体系/一键布局/路由预演/发布 diff）**原样成为"流程"区块**，本设计不重做。
- gateway 版原型（agent-gateway-v1/prototype）的收件箱/名册/审计交互范式在此吸收：任务中心≈收件箱简化版、Agent 名册≈目录页签、审计回放≈证据链时间轴——收敛掉的是"策略中心/信任档"（v2）。

## 6. 交付切分

P0（M-C 前）：部门树/用户/角色/Agent/凭证五页 + 流程区块并入；P1：任务中心/实例查询/审计检索/webhook；P2：指标看板/多语言（UIA-02）。前端工程纪律：不引入新 UI 框架（沿用 designer 依赖），列表页优先表格组件复用。
