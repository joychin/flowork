# flowork 引擎 v1 · 企业级能力清单与排期

> 要求④的落点："其他企业级能力你自己调研后加进来"。基准：Camunda 8 自管版（JWT 认证/Identity RBAC/Optimize 分析/K8s HA/SOC 2，[docs.camunda.io](https://docs.camunda.io)）、n8n 企业版（SSO/LDAP、日志流式外送、环境与 Git 配置化、外部密管、队列模式，前期调研）、Temporal（版本化/命名空间）、Automation Anywhere（管理端 API 任务审计日志，[docs](https://docs.automationanywhere.com)）。结论：**企业级不等于全做**——按"独立部署的底线企业集"（v1）与"中标大客户集"（v1.1/v2）分层。

## 2. "底线企业集"的辩护（为什么 v1 只做这些）

独立部署卖给"有审批痛点的中型组织与集成商"（v1 客户画像，00 §5），其采购硬门槛是：**部署得起（A1-A3）、管得住（B 前三项）、看得见（C 前三项）、接得上（D 前两项）**——即上表 ✅ 集。SSO/同步/多租户是大客户与 SaaS 化命题，提前做会把 v1 拖成平台工程；而 hash chain 审计、三面来源可辨、升级不中断是**便宜的差异化**（Camunda 们要整套 Identity/Optimize 才给），优先做。

## 4. 风险

| 风险 | 缓解 |
|---|---|
| 企业功能吸干 v1 迭代 | ✅ 集冻结进 v1 里程碑（M-C 验收）；P1 项进 v1.1 池按客户拉动排序 |
| hash chain 写放大/锁竞争 | 同事务单行哈希成本极低；重字段异步补全（08 §6） |
| OIDC 引入外部依赖破坏"独立部署自洽" | 做成可选 provider，默认本地凭证体系永在 |
