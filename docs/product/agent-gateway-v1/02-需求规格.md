# flowork 审批网关 v1 · 需求规格

> 第 2 篇。功能需求全部溯源到 [01-用户故事](01-用户故事.md) 的 US 编号。优先级：P0=发布门槛（缺一不可发）；P1=发布目标（尽量含）；P2=已排期下版本。

## 1. 范围

**In scope（v1.0）**：Agent 接入（MCP+HTTP）、审批请求生命周期（提交/路由/办理/超时/驳回回路）、网页收件箱、钉钉+飞书卡片、Agent 身份注册与停用、风险策略（版本化+diff+模拟）、证据链查询与制度版本时间线、自托管一键部署、**人发起申请（极简表单 + 申请类型模板 + AI 预审混编，汇入同一管道）**。

**Out of scope（明确不做，防蔓延）**：表单设计器与字段权限矩阵、N 级主管链与递归升级（v1.1）、临时凭证/TTL 数据授权（v2）、信任爬坡自动建议（v1.1）、CS108 报告模板（v1.1）、行业模板仓、AI HR、A2A、生成包、多租户托管云（先单租户自托管）、发票 OCR/预算系统对接、迁移钉钉-飞书原生审批存量（IM 内发起见 US-605，v1.1）。

## 3. 非功能需求（NFR）

| ID | 维度 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 自动通过路径端到端 P95 < 200ms（含审计落库）；卡片投递 < 60s（P99）；收件箱列表加载 < 500ms（万级待办） |
| NFR-02 | 可用性 | 单实例自托管即可运行；无外部强依赖（默认 SQLite）；worker 与 web 分离部署时 web 宕机不影响在途审批的引擎侧推进（超时/升级仍执行） |
| NFR-03 | 安全 | agent 凭证哈希存储、仅创建时明文一次；所有写操作带 actor 归因（acted_by / acted_as_agent 双链）；API 全量鉴权，无匿名写 |
| NFR-04 | 审计完整性 | 审批/审计记录只追加，无 UPDATE/DELETE 路径；policy 版本不可变；每条证据可追溯 policy_version_id |
| NFR-05 | 合规映射 | 审计字段集预留 CS108「审计与合规」评估项映射（提议者身份/授权范围/依据版本/时间戳/意见） |
| NFR-06 | 可运维 | naive UTC 时间戳（沿用 flowork.clock）；结构化日志含 request_id 贯穿；升级迁移向后兼容（v1 数据可升 v1.1） |
| NFR-07 | 国际化 | 控制台文案中英双语资源化（首发中文，英文包 v1.1）；卡片文案同源 |
| NFR-08 | 兼容性 | 引擎核心零侵入——新增能力只经 SPI（Notifier）、新模块（mcp/authorization）与 web 路由组接入，不违反 AGENTS.md 硬约束 2/3 |

## 4. 发布验收门槛（DoD）

1. 全部 P0 FR 通过验收（对应 US 的 Given/When/Then 逐条核验）。
2. 端到端演示脚本可复跑（见 [04-原型设计说明](04-原型设计说明.md) §3 演示脚本的工程版）：外部 MCP 客户端发起退款 → 飞书卡片批准 → agent 收到结果 → 控制台回放证据链，全程 < 3 分钟；**加一笔人发起报销（AI 预审 → 直属主管）与 Agent 请求在同一收件箱混排**。
3. 工程四道门全绿：pytest（新增模块覆盖 ≥ 90%）+ ruff + mypy strict。
4. 自托管冒烟：docker compose up 后跑通同一脚本。
5. 文档齐备：接入指南（10 分钟版）、策略配置指南、审计导出说明。

## 5. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 钉钉/飞书卡片审核与 API 变动 | FR-201 延期 | 卡片抽象为 Notifier 适配器，两通道并行开发；先做 webhook 通用版兜底 |
| 策略 DSL 过早复杂化 | 交付延期 | v1 限"动作类型+数值档位"两种条件，其余进 v1.1 |
| 审批人解析依赖组织数据 | P0 阻塞 | v1 内置极简目录（用户/角色/主管三人表 + CSV 导入），OrgDirectory SPI 对接企业真实目录进 v1.1 |
| wait_for_result 长连接资源 | 并发瓶颈 | v1 长轮询（30s 间隔），SSE/webhook 后续 |
