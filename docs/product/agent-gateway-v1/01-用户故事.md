# flowork 审批网关 v1 · 用户故事

> 产品定义第 1 篇。定位与终局见 `docs_research/flowork最终形态-组织授权层-2026-10.md`；场景素材见 `docs_research/flowork最终形态-使用场景-2026-10.md`。本文把九大场景中属于 2026 首发范围的部分（场景 1/3 + 控制平面雏形）展开为可开发的故事集。

## 1. 产品一句话（v1 范围）

**组织里每一个"要做某事"的请求——无论发起者是 AI 还是人——都走同一条授权管道**。Agent 侧：一行调用提交审批 → 按风险策略路由（自动通过 / 人审批 / 拒绝）→ IM 卡片或网页收件箱办理 → 全程留证可回放。人侧：经典申请（报销/请假/采购）经极简表单汇入同一引擎、同一收件箱、同一审计。

v1 对应终局四层中的：协议层首版动词集（MCP 工具面）+ 引擎层（现有内核直接复用）+ 控制平面的三个核心视图（收件箱 / Agent 名册 / 策略中心 / 审计回放）。

把人发起的经典审批收进 v1 是刻意的 GTM 决策：**冷启动**——Agent 到来之前，组织已有的报销/请假流量让收件箱先有日常流量、审批人先养成习惯（"workflow gravity"）；**审计统一**——"组织授权层"覆盖所有 actor，人提的和 AI 提的同一条证据链；**引擎免费**——BPM 内核本来就会，缺的只是产品面（见 E6）。

## 2. 角色（Personas）

| ID | 角色 | 画像 | 核心诉求 | 对应终局位置 |
|---|---|---|---|---|
| P1 | **阿凯 · Agent 应用开发者** | 写 agent 应用的工程师，用 Claude Code/自研框架/LangGraph | 10 分钟接入，不研究 BPM 概念；挂起-恢复别把我 agent 搞崩 | 协议层的使用者 |
| P2 | **老周 · 审批人**（财务/店长/值班工程师） | 手机上办事的业务负责人 | 一眼看懂 AI 要干什么、有什么风险；一键批/驳；别让我背锅 | 控制平面的消费者 |
| P3 | **林姐 · 组织管理员**（IT/安全负责人） | 决定"哪些 AI 能干什么"的人 | 发上岗证、定风险策略、出事后能回收 | 控制平面的管理者 |
| P4 | **何敏 · 审计/合规** | 应对内审外查（含 CS108 类评估） | 每笔 AI 行为"谁批的、按哪版制度"一秒可答、可导出 | 控制平面的付费方 |
| P5 | **大刘 · 自托管运维** | 在自己机房/私有云跑 | 一条命令起服务；升级不丢审计 | 引擎层的宿主 |
| P6 | **小陈 · 普通员工（申请人）** | 要报销/请假的普通人 | 一分钟提交；随时看进度；驳回后知道怎么改 | 授权层的人侧用户 |

## 3. 史诗（Epics）与故事

优先级：P0=v1 必须；P1=v1 尽量；P2=v1.1/v2。验收标准用 Given/When/Then。

### E1 接入（主角：阿凯）

**US-101（P0）十分钟接入 MCP**
作为阿凯，我希望在 MCP 客户端填一个 endpoint + token 后，agent 就能调用 flowork 的审批工具，以便不给 agent 框架做任何改造。
- Given 已注册 agent 并拿到凭证，When 在 Claude/任意 MCP 客户端配置 flowork server，Then 工具列表出现 `flowork_propose` 等工具且可调用成功。
- Given 未注册或凭证失效，When 调用任一工具，Then 返回 401 + "如何注册 agent" 的指引文案，而非裸报错。
- Given 同一 agent 并发调用，Then 不产生交叉污染（请求互不串扰）。

**US-102（P0）提交审批请求**
作为阿凯，我希望 `propose(action, payload, idempotency_key)` 一步提交并拿回请求号，以便 agent 端逻辑简单。
- Given 合法动作与载荷，When 提交，Then 返回 `request_id`、`status`（auto_approved/pending_approval/rejected_by_policy）、`route`（预估审批链：哪些节点、是否会签）。
- Given 相同 `idempotency_key` 重放，Then 返回原 `request_id`，不产生新单。
- Given 载荷超限（默认 64KB），Then 返回明确错误码，不落库。

**US-103（P0）等待与查询结果**
作为阿凯，我希望 `wait_for_result(request_id, timeout)` 挂起等待、`get_status` 随时查询，以便适配轮询型和长任务型 agent。
- Given 请求已决，When wait，Then 立即返回终态（approved/rejected/expired）+ 意见与拒绝码（若有）。
- Given 未决且未超时，When wait，Then 保持挂起；超时后返回 `pending` 状态而非异常。
- Given 驳回，Then 返回结构化 `rejection`（意见、拒绝码、cause 链到原单），agent 可据此整改重提（新 request_id，`supersedes` 指向旧单）。

**US-104（P0）自动通过零感**
作为阿凯，我希望命中自动通过策略时同步拿到 approved，以便低风险动作不被审批拖延。
- Given 命中 auto-pass 规则，When propose，Then 同步返回 approved，端到端 P95 < 200ms，且审计事件已落库（含命中的规则与 policy 版本）。

**US-105（P1）Python SDK 与 HTTP 双通道**
作为阿凯，我希望除 MCP 外还有 `pip install flowork` 后 `flowork.request(...)` 的 SDK 与纯 HTTP API，以便非 MCP 的运行时也能接入。
- Given SDK 一行调用，Then 与 MCP 路径行为一致（同一 request 语义）。

**US-106（P2）Webhook 回调**
作为阿凯，我希望注册回调 URL 在请求终态时被通知，以便事件驱动型 agent 不必轮询。

### E2 审批（主角：老周）

**US-201（P0）IM 审批卡片**
作为老周，我希望在钉钉/飞书收到审批卡片——动作名、参数摘要、风险徽章、AI 的理由、批准/驳回/转办按钮，以便 30 秒内办完。
- Given 新待办命中我，When Notifier 投递，Then 1 分钟内卡片到达；卡片含"谁（哪个 agent、什么身份）在请求什么（参数摘要）依据什么（命中的策略与限额）"。
- Given 我点击批准，Then 卡片翻转为"已批准"且不可重复操作，引擎办件落痕。
- Given 超时已升级，Then 卡片置灰显示"已升级至 XX"，防过期操作。

**US-202（P0）网页收件箱**
作为老周，我希望网页收件箱按风险与 SLA 排序看全部待办，以便集中处理。
- Given 我有待办，When 打开收件箱，Then 列表按风险降序、同风险按剩余 SLA 升序；每行显示风险徽章、金额/对象、提议 agent、剩余时间条。
- Given 低风险待办多条，When 我批量批准，Then 逐条落痕（每条独立 actor/时间），任一条失败不影响其余。

**US-203（P0）驳回必须给意见**
作为老周，我希望驳回时填意见（可选拒绝码），意见回传给 agent，以便 AI 能整改而不是原样重提。
- Given 我点驳回，When 意见为空，Then 不可提交；意见与拒绝码进入审计链并随终态返回给 agent。

**US-204（P0）转办**
作为老周，我希望把待办转给同事并留痕，以便职责对的时候才批。
- Given 转办，Then 原 acted_by=我(转出)、新办理人=同事，历史完整可见，卡片投递给新办理人。

**US-205（P1）会签视角**
作为老周，我希望会签单显示"已批/未批名单"，以便知道还差谁。
- Given 会签出口=all 且 2 人中 1 人已批，Then 卡片与收件箱显示"已批：财务-张三；待批：店长-李四"。

**US-206（P0）超时升级通知**
作为老周，我希望超时后原审批人收到"已升级"提醒、上级收到新卡片，以便流程不堵死。
- Given 超时规则触发（如 2h），Then 任务升级至上级（复用引擎 Jobs 超时 + 参与者升级），双方各收到对应通知。

### E3 策略与身份（主角：林姐）

**US-301（P0）注册 Agent 发上岗证**
作为林姐，我希望创建 agent 身份（名称、负责人、凭证）并设初始信任档，以便每个 AI 有名有姓有归属。
- Given 创建成功，Then 凭证仅展示一次；列表显示身份、负责人、状态（试用/在岗/停用）、当前 policy 版本。
- Given 停用，Then 进行中请求冻结或按策略转人，新请求一律拒绝；操作即时生效并留痕。

**US-302（P0）风险策略配置**
作为林姐，我希望按"动作类型 + 条件（金额档位等）"配置路由：自动通过 / 审批链（人、角色、主管）/ 直接拒绝，以便制度变成机器可执行的规则。
- Given 我编辑规则表，When 保存草稿，Then 可预览 diff（与线上版本对比，复用现有发布 diff 交互）。
- Given 发布新版本，Then 新请求按新版本路由；在途请求按其发起时的版本完成（定义快照隔离，引擎已有语义可直接复用到策略层）。

**US-303（P1）限额与信任爬坡**
作为林姐，我希望给 agent 配自动通过额度、日动作上限、连续驳回降级规则，以便信任随表现增长。
- Given 试用期 agent 单笔 > 限额，Then 强制转人审；日上限达到后当日剩余动作全部人审或拒绝（按配置）。

**US-304（P0）审批人解析**
作为林姐，我希望审批链里写"直接主管/角色/固定人"，引擎自动解析到具体人，以便组织变动不用改流程。
- v1 支持：固定人、角色、直接主管（DirectManager）。N 级主管/递归升级进 v1.1（引擎 participants 扩展点已预留）。

**US-305（P1）策略模拟预演**
作为林姐，我希望改策略前用模拟器输入"动作+金额+agent"看会走哪条链，以便发布前心里有数。
- Given 模拟输入，When 提交，Then 返回命中规则与完整路由预览（复用现有 dry-run/路由预演能力，不产生真实实例）。

### E4 审计（主角：何敏）

**US-401（P0）证据链查询**
作为何敏，我希望按时间/agent/动作/审批人/状态检索，并展开任一请求的完整证据链，以便回答"这笔谁批的"。
- Given 任一请求，Then 链上每个节点可见：actor（区分 AI/人，AI 显示身份与版本）、动作、时间、依据（policy 版本 + 命中规则）、意见。
- Given 查询，Then 只读；历史不可修改不可删除（只追加语义对外可见）。

**US-402（P1）一键导出合规报告**
作为何敏，我希望勾选多条导出 CSV/PDF，字段对齐 CS108 审计与合规项，以便迎检材料不用手工拼。
- Given 导出，Then 报告含：请求明细、证据链、policy 版本信息、统计摘要。

**US-403（P0）制度版本时间线**
作为何敏，我希望看到 policy 的版本演进——谁改的、改了什么、何时生效，以便"按哪版制度"可证。
- Given 版本列表，Then 每版含发布人、时间、diff 摘要、生效范围。

**US-404（P1）时间轴回放**
作为何敏，我希望以时间轴形式回放单笔审批全过程，以便向监管/管理层讲述清楚。
- Given 打开回放，Then 按时间展示提议→策略求值→通知投递→每级审批（或超时升级）→执行回执；AI 与人用可区分的视觉标识。

### E5 运维（主角：大刘）

**US-501（P0）一条命令自托管**：docker compose up 后引擎+控制台+worker 全部可用，数据落本地 SQLite/Postgres。
**US-502（P1）多副本安全**：Job CAS 认领已保证恰一次；文档化部署拓扑（web×n + worker×m 共库）。
**US-503（P1）健康与指标**：/health、审批量/时延/超时率/自动通过率指标（v1 暴露 Prometheus 文本端点）。
**US-504（P2）审计留存策略**：只追加冷热分层与归档导出。

### E6 人发起的申请（主角：小陈）

> 边界声明：v1 只做"极简表单 + 申请类型模板 + AI 预审混编"，**不做表单设计器、不做发票 OCR、不去迁移钉钉/飞书原生审批的存量**——定位是"汇入同一条管道"，不是替代现有审批产品。

**US-601（P1）一分钟提交报销**
作为小陈，我希望在控制台填一张极简表单（类型/事项/金额/附件）提交报销，以便走和 AI 同一条审批管道。
- Given 我选"报销"填金额 ¥2,380，When 提交，Then 生成 request（提交人=我，acted_by 归因留痕），按报销模板路由：≤1,000 直属主管单签；>1,000 直属主管 → 财务。
- Given 提交成功，Then "我的申请"可查状态；审批人的收件箱与 IM 卡片同步出现（与 Agent 请求完全同构）。

**US-602（P1）我的申请与整改重提**
作为小陈，我希望随时看进度、被驳回时看到意见并整改重提，以便不反复跑腿。
- Given 被驳回（意见+拒绝码），Then 我能看到意见，整改重提挂 supersedes 链（与 Agent 路径同构，审计可看"第 N 次提交"）。
- Given 审批中，Then 可查当前节点与等待人；催办按钮 v1.1。

**US-603（P1）人机混编申请**
作为小陈，我希望报销先过 AI 预审（发票要素校验 Agent）再给人批，以便低级错误不用人来挑。
- Given 申请类型配置了 AI 预审节点，When 提交，Then 先由指定 Agent 自动校验：通过→进入人审批；不通过→直接驳回并附原因；证据链中 AI 与人节点并存可回放。

**US-604（P1）申请类型模板管理**
作为林姐，我希望用 JSON/YAML 定义申请类型（字段列表 + 关联流程/规则 + 版本化），以便新增"采购申请"不需要开发排期。
- v1 字段类型限：文本/数字/金额/附件，无设计器。
- 模板版本化复用定义发布范式（diff 预览 + 快照隔离）。

**US-605（P2）IM 内发起**
作为小陈，我希望在飞书/钉钉对话里 @flowork 机器人直接发起报销（表单卡片），以便不开网页。
